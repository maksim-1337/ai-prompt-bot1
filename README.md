# NewsLightGG — редакторская очередь

Каждый час система собирает свежие новости и отбирает до трёх материалов на ревью.
Одновременно в работе не больше трёх `review`/`approved`: очередь не заваливает редактора,
существующий текст не перезаписывается. Если достойных новостей нет, новых черновиков может быть ноль.

**В @newsLightGG публикуются только Markdown-черновики со статусом `approved`.**
Ожидание часа или дня ничего не одобряет. Новые материалы всегда получают `review`.
В канале только текст: первая строка с главным фактом, 1–3 коротких абзаца, уместная живая концовка.
Формулировки @yep_news не используются как исходник.

## Где редактировать

Открой [черновики](data/drafts/review/) → нужный файл → карандаш **Edit**.
Внутри файла:

1. Измени текст между `<!-- POST -->` и `<!-- /POST -->`. Только этот текст отправляется.
2. Проверь источник, дату самой новости и смысл. Служебные поля и факты для сверки остаются в GitHub.
3. Вверху замени `status: review` на `status: approved` и сохрани через **Commit changes** в `main`.
   Для пропуска поставь `status: skip`. Чтобы оставить на потом — `review`.

Если GitHub предлагает отдельную ветку, публикация начнётся только после попадания правки в `main`.
`approved` запускает Actions сразу после push; время старта зависит от очереди GitHub.
На push выполняется только отправка одобренного, без загрузки текстовой модели.
Расписание — `17-я минута каждого часа UTC`; GitHub может задерживать плановые запуски.

После подтверждения Telegram статус становится `published`, в черновике появляются
`message_id` и `published_at`. [История](data/editorial-history.json) хранит источник,
`url`/`source_url`, ссылку на Telegram, текст и отпечаток одобренной версии.

## Отбор и пересказ без платного API

Разрешены технологии/ИИ, игры, соцсети, интернет, кино, сериалы, наука, спорт, политика.
Редакционные RSS: 3DNews, iXBT, Lenta, РИА Новости, Коммерсантъ.
Авторские статьи Habr, недатированные новости, материалы старше 18 часов, реклама,
биржевая рутина, обзоры/скидки и явный кликбейт исключаются. Спорт проходит только для
крупных событий; для политики требуется значимое решение. Есть проверка дублей по URL и заголовкам.
Это строгие эвристики отбора, а не доказательство достоверности или популярности.

Пересказ делает [локальная русскоязычная модель](https://huggingface.co/cointegrated/rut5-base-paraphraser)
на CPU в GitHub Actions. Модель и зависимости кэшируются. OpenAI-токены, фото и image API не используются;
`OPENAI_API_KEY` в workflow не передаётся. Модель может ошибаться: имена, факты, даты и оговорки проверяет редактор.
Автопроверки ловят изменения чисел, латинских названий, отрицаний и дословные длинные фрагменты,
но не заменяют проверку смысла человеком.

Если модель недоступна или пересказ не прошёл проверки, в `review` появляется карточка с
исходными фактами и пометкой «Нужна ручная редактура». Заготовка с `[ДОПИШИ ...]` не может
публиковаться, даже если случайно поставить `approved`: сначала нужен законченный текст.
Расхода платного inference API нет; вычисления используют обычные лимиты GitHub Actions.

## Защита публикации и восстановление

- Токен остаётся в **Settings → Secrets and variables → Actions → TELEGRAM_BOT_TOKEN**.
  Он передаётся только шагу отправки; сборщик/локальная модель токен не получают.
- Все старые отправители отключены, в том числе таймер `pending.json`, фото, прямой текст,
  тестовый live-post и отправка студией в каналы. Video Studio workflow приостановлен.
- Старая очередь сохранена в [архиве](data/drafts/archive/legacy-pending.json).
  Неопубликованное перенесено в `review`, прежние подтверждения — в историю.
  У старого черновика неизвестная дата оставлена пустой: перед `approved` её нужно проверить.
- Возраст проверяется повторно перед отправкой. Устаревший `approved` возвращается в `review`.
  При часовом сборе `review` старше 18 часов переводится в `skip`: текст сохраняется,
  а место освобождается для свежих новостей. Отмена до вызова Telegram допускает повторное
  одобрение; предыдущая отмена сохраняется отдельно в `cancelled_attempts` истории.
  Не обновляй дату ради обхода проверки: она относится к новости, а не к редактированию файла.
- До отправки намерение `sending` записывается и отправляется в GitHub; после — подтверждение.
  Если запись/отправка GitHub не удалась, Telegram не вызывается.
- После таймаута или обрыва результат `uncertain`/`sending` блокирует автоматический повтор.
  Сначала проверь канал и артефакт `editorial-recovery-...` в Actions. Если сообщение существует,
  восстанови `published` и реальный `message_id` из подтверждения. Никогда не удаляй запись
  истории без проверки канала. У Telegram нет ключа идемпотентности: неизвестный результат требует ручного разбора.
- Параллельные workflow последовательно выполняются в одной группе. Последняя версия
  одобрения перепроверяется после записи намерения; изменение текста или статуса останавливает отправку.
  Git-конфликт сохраняет артефакт и требует разрешения, принудительного push нет.

## Проверка

```sh
python -m pip install -r requirements-editorial.txt
python -m unittest discover -s tests -p test_editorial.py -v
python -m compileall -q editorial draft_queue_runner.py
python -m editorial.desk check
```

Команда без режима выполняет только проверку. Живая отправка разрешена только workflow на
`main` с `publish --git`; тесты используют подставной Telegram и временные каталоги.
**Run workflow** безопасно собирает кандидатов, но также публикует уже имеющиеся `approved`.

[Журнал запусков](https://github.com/maksim-1337/ai-prompt-bot1/actions/workflows/news-autopilot.yml).
Старая документация студии сохранена в [архивной инструкции](docs/LEGACY_STUDIO.md);
её расписание и правила отправки больше не действуют.
